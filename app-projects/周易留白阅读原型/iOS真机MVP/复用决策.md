# iOS 真机 MVP 复用决策

日期：2026-08-07

## 核心需求与检索词

- SwiftUI WKWebView local HTML resources iOS
- WKURLSchemeHandler local assets Swift
- offline web app wrapper iOS WKWebView

## 选择

复用本机已验证的 SwiftUI + `WKWebView` + `WKURLSchemeHandler` 架构，但不复制其他产品的业务代码、素材或文案。项目不引入 CocoaPods、SPM 或跨端运行时。

必须自研的差异部分：周易资源清单、典籍文本 MIME、纵向全屏安全区、声音由用户手势启动、离线边界和真机验收。

## 2026-08-07 投币音效与触觉补充

- 检索词：`WKWebView JavaScript bridge haptic Swift`、`UIImpactFeedbackGenerator WKScriptMessageHandler`。
- 候选：[Lision/WKWebViewJavascriptBridge](https://github.com/Lision/WKWebViewJavascriptBridge)（MIT、1.3k stars、近期维护）功能成熟，但对单一触觉事件过重；其余小型桥接示例维护度或许可证信息不足。
- 选择：不新增依赖，使用系统 `WKScriptMessageHandler` 接收网页投币事件，以 `UIImpactFeedbackGenerator` 生成触觉；铜钱声继续使用本地 Web Audio 合成。
- 自研差异：三枚铜钱的分层金属泛音、落定节奏与轻—轻—中触觉强度；普通浏览器无触觉桥时自动静默降级。
- 真机补充：iOS 投币声改由 `AVAudioPlayer` 播放运行时生成的 PCM/WAV 铜钱音，避免 `WKWebView` 音频会话静默；仅在用户主动开启声音后启用，Web 端保留 Web Audio 回退。

## 2026-08-07 中英文完整性补充

- 检索候选：`i18next/i18next`（MIT、8.6k stars、活跃）成熟但对当前单文件、双语言、离线原型偏重；React/Next 绑定方案与现有架构不匹配。
- 选择：继续复用项目已有 `Map + 动态模式匹配` 翻译层，不新增依赖。
- 自研差异：中文模式不显示英文缩写；英文模式覆盖八卦、六十四卦名、动态爻位、典籍元数据，并为保留的经典中文原文强制附英文来源说明。

## 2026-08-07 内测完成度加固补充

- 检索词：`WKWebView Swift`、`SwiftUI WKWebView wrapper iOS`、`WKWebView Javascript bridge`。
- 候选：[Lision/WKWebViewJavascriptBridge](https://github.com/Lision/WKWebViewJavascriptBridge)（MIT、约 1.3k stars、近期维护），桥接成熟但对当前两类本地消息过重；[kylehickinson/SwiftUI-WebView](https://github.com/kylehickinson/SwiftUI-WebView)（Unlicense、约 360 stars、近期维护），适合通用网页包装但无法替代本项目的离线资源协议与反馈边界；[XWebView/XWebView](https://github.com/XWebView/XWebView)（Apache-2.0、约 470 stars、近期维护），扩展能力完整但当前不需要额外运行时。
- 选择：继续使用系统 `WKWebView`、`WKURLSchemeHandler`、`WKScriptMessageHandler`、`AVAudioPlayer` 与 UIKit 触觉 API，不新增包依赖。
- 理由：现有实现已经覆盖离线资源、JS→原生声音/触觉与自动签名；新增第三方包装会扩大二进制、许可证与故障面，却不能替代本项目需要的原生加载失败恢复、App 图标、六爻进度和经典内容边界。
- 必须自研：本地资源加载状态与重试、取消中的 Scheme Task 防护、太极八卦 App 图标、中文优先错误界面，以及英语人工审校门禁。

## 2026-08-07 竞品驱动的随机信任与导航补充

- 检索词：`iching`、`i-ching`、`yijing`、`SwiftUI onboarding`。
- 候选：[kentang2017/ichingshifa](https://github.com/kentang2017/ichingshifa)（MIT，277 stars，2026-06 仍有推送）可参考筮法领域模型，但存在未解决的历法/爻位问题；[chengjun/iching](https://github.com/chengjun/iching)（MIT，126 stars，2025-08 最近推送）为 Python/JavaScript 筮法实现，不直接匹配 iOS；[Nodle-I-Ching](https://github.com/NodleCode/Nodle-I-Ching)（GPL-3.0，已归档）不采用；[zzkt/i-ching](https://github.com/zzkt/i-ching)（GPL-3.0，64 stars）仅作资料结构参考；[OnboardingKit](https://github.com/danielsaidi/OnboardingKit)（MIT，1.2K stars，活跃）为成熟 SwiftUI onboarding 组件，但当前只需两个小范围流程改动，引入包过重。
- 决策：不 Fork、不新增第三方依赖。数字投币复用浏览器/WebKit 的 `crypto.getRandomValues`，并保留可测试的随机函数注入；阅读上一段复用现有状态机，不引入新导航框架。
- 自研差异：“问题/方向不操纵卦象”的人类可读说明、六爻进度、具有语义的返回上一段，以及不强化“未来卦”。
