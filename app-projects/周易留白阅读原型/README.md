# 周易留白阅读原型（中文优先）

> PROTOTYPE / 本地收费基础能力。当前只保留“即时问事”入口；它是一段不替用户预测的私密 I Ching 反思仪式。个人底色已从产品流程撤下且运行时不可达。不是正式产品，不含后端、账号、云同步、真实付款或发布能力。

## 启动

```bash
corepack pnpm start
```

打开 `http://127.0.0.1:4174`。

## 当前入口

- **问一件事：** 先选择感情、事业、金钱、家庭、变化或自我，再填写可留空的问题。默认点击三枚方孔铜钱进行动态投掷：每轮三枚同时落定并自动记一爻，共六轮，由初爻到上爻；也可切换为手动记录。系统据此计算本卦、变爻和之卦。关注方向只影响最后的开放式提示，不操纵卦象。

“个人底色”（八字、星宿、星座、紫微）不在当前产品流程中展示；历史实验文件被隔离，服务器、iOS 资源加载器和同步脚本均不加载它们。

每次完成六爻后，问题、卦象与随机来源会自动保存在当前设备的版本化本地历史中；不要求用户当场写理解。标签、搜索、删除、回看日期和回看备注均为可选。JSON 导入/导出经过 schema 与数据校验；导出前会主动提示文件是可能含私密问题与备注的未加密明文。

## 本地历史与内容边界

- 历史 schema 当前为 v2；可迁移 v1，无法读取的数据进入本机隔离记录而不混入有效历史。单库最多 500 条、约 2 MiB，超限只移除最旧记录。
- 六十四卦原文数据继续为起卦结果与典籍库服务；“学习与主题”产品入口已撤下，不加载为可达功能。
- 起卦结果在一个连续页面中呈现结构、卦辞/大象、变爻、之卦、开放式导读与来源入口。直译层状态、背景说明与多观点边界均在同页说明；经典中文原文在英文界面保留 `lang=zh` 标记并附英文说明。
- 未使用机器翻译，也未捆绑未经许可的现代译本。James Legge 仅作可追溯公版来源/结构说明；当前不伪称已经提供完整多译本。

## 声音与动效

- 声音和中英文切换集中于右上角齿轮的“偏好设置”；声音默认关闭，必须由用户主动开启；不会自动播放。
- 环境声由浏览器本地 Web Audio 实时合成，以稀疏五声音阶、低声部持续音和轻泛音构成，不加载外部音乐文件。
- 动态投掷开启声音后会有三枚铜钱依次落定的轻金属声；阅读逐层展开时只有极轻提示音。
- 太极标识、背景气息和开放问题采用克制的缓动；系统“减少动态效果”设置会停用持续动画。

## 典籍库

- 首页可进入“典籍库”，按书名或分类筛选并按需展开全文；不会在首页一次加载全部文本。
- 用户提供的 ZIP 中 18 个条目全部保留在 `content/classics/library/`，逐文件字节数、行数、SHA-256、重复关系和来源状态记录于 `manifest.json`。
- 18 个条目包含 16 份不重复内容：《论语》《孟子》分别在“十三经”和“四书”目录重复，文件哈希完全相同。
- 《仪礼》《春秋公羊传》《尔雅》原文件自带“来源待确认”标记；界面会如实显示。
- D 版阅读完成后，关注方向会带出一条人工核对的“同题旁证”。旁证明确标注出处，不改变卦象，也不冒充卦辞。

重建或核对典籍库：

```bash
corepack pnpm build:classics
corepack pnpm check:classics
```

## 结果阅读流

- 通过正常入口完成六爻后，结果在一个主纵向滚动容器内连续展开；不要求逐段点击“继续”，不使用遮挡正文的步骤图层。页内目录只辅助定位，不隐藏正文。
- 直接以 `&view=reading` 打开时仍是设计样片，不冒充新起的卦；真实起卦请从首页进入。

结果末尾的三条开放式问题不再是按方向写死的模板：第一条来自本卦独有的观察角度，第二条来自静卦或变爻位置，第三条结合用户选择的关注方向。六十四卦均有独立内容，同一卦象输入保持可复现；这些问题不更改卦象，也不替用户作答。

## 内容与依赖来源

- 用户提供的 `Chinese-Classics-TXT.zip` 已接收至 `vendor-input/`；完整条目位于 `content/classics/library/`，《周易》早期单独抽取文本仍保留在 `content/classics/周易.txt`。压缩包汇编来源与授权说明尚未确认，因此只限内部原型。
- `content/iching/hexagrams.json` 由上述《周易》原文生成，含 64 卦的卦辞、大象与六爻文本。可用 `corepack pnpm build:iching` 重建，用 `corepack pnpm check:iching` 核对。
- `lunar-javascript@1.7.7` 与 `iztro@2.5.8` 的历史实验文件仍保留在 `vendor/`，但不属于运行时依赖，也不会同步进新的 iOS Web 构建输入。
- 依赖许可证副本位于 `vendor/licenses/`，复用判断位于 `docs/GitHub复用决策记录_2026-08-01.md`。

## 明确不做

- 不要求用户当下写解释、答案或反思。
- 不生成预测、吉凶评分、准确率或重大决策建议。
- 不使用未获授权的现代译本；动态起卦结果目前只展示用户资料中的经典原文，不自动伪造现代解释。
- 不保存出生资料。完成的卦象历史自动保存在本机；其他未完成表单态刷新即丢失。
- 不部署、不接 API、不创建数据库。
- 不自动播放声音，不嵌入来源不明的音乐或音效素材。
- 不根据关注方向挑选卦象或改写经典原文。
- 不把基础盘面自动转换成性格定论、流年断语或医疗、金融、法律、安全及重大关系建议。
- 不把星座或日主的宽泛描述包装成科学心理测评；用户回应不生成准确度、人格类型或诊断结论。

## iOS 与收费骨架的真实状态

`iOS真机MVP/` 是 SwiftUI + `WKWebView` 离线容器。StoreKit 2 接口覆盖商品加载、已验证权益、交易更新、购买结果、完成交易与显式恢复；已验证的权益会经受控 Swift ↔ Web bridge 下发为 `free`/`lifetime`/`subscription`，用于实际门控完整历史与导出。`LocalProducts.storekit` 仅供 Xcode 本地测试，Scheme 已选中该配置。没有创建 App Store Connect 商品、订阅、账号或真实交易。免费层始终保留核心起卦与最近 5 条历史；买断/订阅只面向完整历史和备份，绝不售卖“更吉利答案”或准确率。

iOS 目标声明 `NSFileProtectionCompleteUntilFirstUserAuthentication`。这是应用容器的数据保护默认值，不覆盖用户主动导出的明文文件，也不等同于端到端加密或云备份。

完整核验：

```bash
corepack pnpm check
```
